## 2. Goal and boundaries

**Observable result.** A person opens `/explorer/` in a browser, signs in through Keycloak, and without choosing a workspace:
- sees the instance, their identity, and the knowledge revision;
- browses and filters authorized entities, opens details, assertions, competing claims, evidence, sources, history, and a bounded neighborhood list;
- reads documents with only their authorized parts;
- previews general and software-task context, with the target, applicability, truncation and continuation shown;
- prepares a ChangeSet in forms, previews it, submits it, reads the validation report, and, as a different person, reviews and applies it;
- if authorized, administers scopes, memberships, re-scopes and profile installation.

Every action is an ordinary `/v1` request made with that person's own access token. The browser receives only server-rendered HTML built from those authorized responses.

**In scope.**
- Browser login (authorization code + PKCE, confidential client), server-side sessions, logout.
- The Explorer module: server-rendered pages, forms, a closed widget set, CSP and CSRF protection.
- Three small **public** API additions needed by the workflows, available to every client (D7).
- A data-only test profile with hostile schema hints (T05).
- Browser tests with a real browser against the real stack, keyboard walkthroughs, and an automated accessibility audit.
- A reproducible browser demonstration.

**Out of scope.**
- Whole-graph visualization, dashboards, rich or collaborative editing, natural-language answers.
- Client-side JavaScript application code (OD1).
- Markdown-to-HTML rendering (D5).
- Production TLS termination, packaging and session persistence across restarts (M13).
- Any change to authorization semantics, ChangeSet rules, context selection or software profiles.
- New knowledge-model features.

**Invariants touched.** AGENTS.md §4.3 (one ChangeSet path), §5.1–§5.3 (current authorization on every request, no client-side filtering), §6.2 (context shown as returned), §7 (target and applicability visible), §9 (same API, untrusted text).

## 3. Decisions to resolve

| ID | Decision | Rationale, evidence, proof obligation |
|---|---|---|
| D1 | **Composition.** A new factory `c1.web.create_web_app(settings)` builds an outer Starlette app with two mounts:<br>• `/v1` → the unchanged `create_app` API, with its `BoundaryMiddleware`;<br>• `/explorer` → the Explorer app.<br>The Explorer calls the API in-process through `httpx.AsyncClient(transport=ASGITransport(api_app))`, sending `Authorization: Bearer <session access token>`. Each call passes through the same middleware, routes, validation, authorization and audit as any external client. `scripts/api.py` serves the web app. With `C1_EXPLORER_ENABLED=false` (the default), the factory returns the API app alone. | Architecture §14 ("same API/session boundary"); AGENTS.md §9. A loopback HTTP hop was the alternative; the in-process transport avoids another port and gives the same code path. **Proof:** an import-boundary unit test fails if `c1.explorer` imports anything from `c1` except `c1.config` and its own package. T01 compares audit records of browser and API-client writes. |
| D2 | **Browser login.** Keycloak client `c1-explorer`: confidential, standard flow only, PKCE S256 required, redirect URI `<C1_EXPLORER_ORIGIN>/explorer/callback`, post-logout redirect `<origin>/explorer/`, and the existing `c1_principal_kind=human` and `c1-api` audience mappers. Its secret is generated into `deployment/.env` by `bootstrap_security.py`. The Explorer sends `state`, `nonce` and a PKCE verifier kept in a short-lived login-transaction record. At the callback it exchanges the code server-side, validates the ID token (issuer, audience `c1-explorer`, nonce, signature through the configured JWKS) **only** to finish login, and keeps the access and refresh tokens server-side. It never sends the ID token to the API. | Architecture §6.1. PKCE also with a confidential client follows current OAuth 2.0 security guidance (RFC 9700). **Proof:** T01 logs in through Keycloak's real login form. Unit tests reject a wrong `state`, a replayed code, a wrong nonce and an ID token used as a bearer token (the API already rejects it: `typ` must be `Bearer`). |
| D3 | **Sessions.** An in-memory session table in the single process: 256-bit random IDs, idle timeout 30 min, absolute 8 h, tokens never logged or rendered. Cookies:<br>• session: `__Host-c1_session`, `Secure`, `HttpOnly`, `SameSite=Strict`, `Path=/`;<br>• login transaction: `__Host-c1_login`, `SameSite=Lax`, 5 min, deleted at callback.<br>Because a `Strict` cookie is not sent on a navigation that a cross-site redirect started, the callback answers with a same-site continuation page instead of a redirect. Refresh happens server-side when the access token has under 30 s left; a failed refresh ends the session. Logout deletes the session and redirects to Keycloak's end-session endpoint. A restart ends all sessions (accepted for M12; M13 decides persistence). | Architecture §6.1 ("secure server-managed sessions"; no secrets in browser storage). Loopback `http://127.0.0.1` is a potentially trustworthy origin, so browsers accept `Secure` cookies there. **Proof obligation, W3:** demonstrate with the pinned Chromium that both cookies work on `http://127.0.0.1:<port>`; otherwise run the test origin as `http://localhost` and record it. |
| D4 | **Requests and CSRF.** Reads are `GET` pages. Every state change is a `POST` form carrying a per-session synchronizer token, and the Explorer also requires a same-origin `Origin` header. Forms use `application/x-www-form-urlencoded`, parsed with the standard library under a 64 KiB cap and with duplicate-key rejection; no multipart. Every response carries `Cache-Control: no-store`, `Referrer-Policy: no-referrer`, `X-Content-Type-Options: nosniff`, and the D5 CSP. Pagination cursors and revision IDs can appear in Explorer URLs; tokens and session IDs never do. | AGENTS.md §5.3 (reauthorize every cursor continuation; the cursor is not an access token). `no-store` keeps restricted pages out of the HTTP cache (T07). **Proof:** T04 and unit tests for missing or wrong CSRF token, wrong `Origin`, oversized and duplicate fields. |
| D5 | **Rendering and widgets.** Jinja2 with autoescape on for every template, and no `|safe` or `Markup` on API data (a lint test greps templates and code). There is **no client-side script**. CSP: `default-src 'none'; style-src 'self'; img-src 'self'; form-action 'self'; frame-ancestors 'none'; base-uri 'none'`. A closed widget set in `explorer/templates/widgets.html`:<br>• plain text; preformatted text (code excerpts, Markdown source, Problem Details);<br>• literal with datatype and language tag; temporal value with precision and unknown bounds;<br>• C1 IRI (internal link only for Explorer routes of C1 resources); external locator (text only, never a link, never fetched);<br>• review state, lifecycle and origin as separate labels; confidence labelled "uncalibrated" unless the API marks it calibrated;<br>• revision/target banner; applicability state; truncation and continuation notice; "excerpt" label with the API's omission markers.<br>Context Markdown and document Markdown are shown as escaped preformatted source. The structured package is shown through widgets. | Spec F09 ("approved presentation widgets"; no executable HTML/JS, no arbitrary fetch); ADR-0015. Converting Markdown to HTML would need a sanitizer and add a risk with no gate value. **Proof:** T05. |
| D6 | **Screens (list/detail, keyboard first).**<br>1. **Home:** instance ID, knowledge revision, principal (`/v1/whoami`), readiness.<br>2. **Entities:** M05 filters (types, label, alias, keywords ANY/ALL, `project_ref`, `valid_at`, `include_unknown`, lifecycle, review state, revision, order) with stable cursor paging.<br>3. **Entity detail:** record, aliases and keywords, assertions with competing claims (`competing_for`), evidence and sources, a history link, and a neighborhood list (direction, predicates, depth ≤ 3).<br>4. **Assertion, source and evidence detail**, with history.<br>5. **History:** newest-first entries; each opens the resource at that revision under current authorization.<br>6. **Documents:** list and search, document view from `/parts` (ordered authorized parts only), Markdown source, export link, history.<br>7. **Context preview:** catalog profiles; anchor, topics, keywords, fields, project filter, revision, budget; for software tasks, target resolution (`/v1/software/targets/resolve`), goal, aspects and the follow-up token. Shows the structured package and its Markdown, and a continuation link.<br>8. **ChangeSets:** list, new, edit, preview, submit, validate, validation report with permission preview, approve, reject, apply, withdraw, rebase.<br>9. **Forms that build operations:** create an entity of an installed class, edit aliases and keywords (`replace`), create a source-backed assertion (source + evidence + assertion in one ChangeSet), install a profile (schema admins).<br>10. **Access administration:** the caller's administered scopes, create and retire a scope, grant and revoke membership, propose a re-scope, list, approve and apply security operations, instance grants.<br>11. **Software:** target resolution and lookup; context pages show the target banner, per-part applicability and `unknown` compatibility.<br>Buttons and forms appear according to API answers, but **visibility is never authorization**: every action is decided by the API. | Spec F09 list; Architecture §14. The profile-selected software widgets are part of the closed set (D5); there is no software-only backend. |
| D7 | **Three public API additions** (also documented in `M12-api.md`; usable by any client):<br>a. `GET /v1/schema`: installed profiles with their classes and properties (IRI, label, description, datatype or range class, cardinality, language-tag rule). ## 7. Recovery and security

| Failure point | Expected safe behavior and recovery |
|---|---|
| Keycloak unavailable at login or refresh | No session is created, or the session ends; the user sees a sign-in error. The API stays fail-closed (readiness false). |
| OpenFGA or TerminusDB unavailable | The API returns 503; the Explorer shows "service not ready" and no cached content. |
| Process restart | All sessions end; users sign in again. No token is on disk. |
| A login callback with a wrong `state`, replayed code or wrong nonce | 400, no session, and the login transaction is deleted. |
| Stolen session cookie | Bounded by idle and absolute expiry, `HttpOnly` and `SameSite=Strict`; logout invalidates it server-side. TLS is required outside loopback (D12). |
| A forged form post | The CSRF and `Origin` checks refuse it before any API call; even past them, the API decides. |
| Revocation while a page is open | Already delivered bytes cannot be recalled. The next request is reauthorized, and `no-store` prevents cache reuse. |
| Hostile stored text | Escaped by autoescape and widgets; no script runs (CSP), no data-derived link or fetch. |

**Secrets.** The `c1-explorer` client secret lives only in the ignored `deployment/.env` and the process environment. Tokens and session IDs are excluded from logs, audit records, HTML, URLs, HAR evidence and reports. Browser evidence is filtered to remove cookies and `Authorization` headers before it is written to `docs/evidence/M12/`.
