## 2. Goal and boundaries

**Observable result.** Authenticated clients list and filter entities, assertions, sources, and evidence at a selected content revision with exact keyword `ANY/ALL`, label/alias, typed property, relationship, review/lifecycle, and valid-time filters; results are deterministic, stably paginated with reauthorized cursors, bounded by fixed limits, and never influenced by hidden data. Bounded neighborhood traversal follows only readable relationship assertions. Manual resolution, reviewed merge, split, and undo preserve canonical identity and history without widening any policy. The `directory` fixture shows one shared Person across Company A and Company B with differently protected contact assertions.

**In scope.** Authorized selection plan and current-binding index; query grammar and compilation; cursors; neighborhood traversal; catalog; export snapshot; identity operations as ChangeSet operation kinds; `directory` fixture and its data-only profile; query-plan tests.

**Out of scope.** Documents and reconstruction (M06), context packages and topic resolution (M07), full-text search, semantic search, backend query pushdown beyond `ids`/type (measured in M13), multi-process index sharing.

**Invariants touched.** AGENTS.md §4.1 (reuse visible identity; no disclosure via duplicate checks; explicit merges preserving references and policies), §5.3 (authorization constrains matching, counts, ordering, traversal, identity lookup; reauthorize every continuation; no positive caches without verified invalidation), §6.1 (exact keywords; bounded traversal; limits fixed and tested; no backend escape hatch).

## 3. Decisions to resolve

| ID | Decision | Rationale, evidence, proof obligation |
|---|---|---|
| D1 | **Authorized selection plan** (`src/c1/query/plan.py`). For a principal: (1) readable scopes = OpenFGA ListObjects `user:<p> reader scope:*` with `HIGHER_CONSISTENCY`; if the result count reaches `min(OPENFGA_LIST_OBJECTS_MAX_RESULTS, C1_MAX_READABLE_SCOPES=500)` or the call exceeds 2 s, the query fails with 422 `C1-QY-050 authorization_set_unbounded` rather than proceeding on a possibly incomplete set; (2) candidate resources = `active` bindings whose `scope_id` is readable and which have no pending operation, taken from the **current-binding index**; (3) the index is an in-process projection of journal `Binding`/`Operation` records keyed by the exact workflow head; it is rebuilt when the head observed at request start differs and discarded on any journal error; a request whose workflow head changes between start and response returns 409 `C1-QY-051 restart_required` (same rule as M03 reads); (4) if candidates exceed `C1_QUERY_CANDIDATE_LIMIT=5000`, fail with 422 `C1-QY-052 candidate_set_too_large` and an explicit hint to add `type` or `scope` narrowing; (5) after filtering, ordering, and paging, the page's resource IDs get a fresh `batch_read`; any denial removes the item and the page is recomputed once, then fails closed. Hidden resources therefore never enter matching, counting, ordering, or traversal. | Architecture §6.3 "obtain bounded allowed resource IDs … apply it in backend query compilation"; §6.3 "do not truncate the authorization set silently"; ADR-0009 index as a security-sensitive projection usable only when not stale. ADR-0013. |
| D2 | **Query grammar** (strict pydantic models, unknown keys rejected with 400 `C1-QY-001`): `types[]` (class or extra RDF type IRIs), `ids[]` (≤200), `label` `{text, mode: exact|prefix, language?}` and `alias` (same shape) matched on lexical values after `c1-kw-1` normalization for `exact` and on casefolded NFKC prefix for `prefix`; `keywords_any[]`, `keywords_all[]` with optional per-item `language`, evaluated by the M02 matching functions; `properties[]` `{predicate, op ∈ eq|ne|lt|le|gt|ge|exists, value: literal|iri}` over readable assertions of the subject with typed comparison on the literal's derived projections (integer, decimal, double, boolean, date bounds) and exact lexical comparison for strings; `relations[]` `{predicate, target_id, direction: out|in}` satisfied only by a readable active assertion whose subject and object are both readable; `review_state[]`, `lifecycle[]`, `scope_ids[]` (narrowing only), `project_ref` (narrowing only); `valid_at` (`xsd:dateTime` with timezone) with `include_unknown: bool`; `revision` (knowledge commit; default head at request time, returned in the response); `order` ∈ `id` (default) | `label` (normalized primary label, then id) | `recorded` (last change commit time, then id); `limit` (default 50, max 200); `cursor`. Evaluation semantics live in `src/c1/query/filters.py` as pure functions over records and are unit-tested against fixed vectors; the backend only fetches candidates. | Spec §6.1 filter list; F02 exact semantics; F04 strict `valid_at` with separate `include_unknown`. |
| D3 | **Compilation and fetch.** Candidates are fetched by canonical class in chunks of 200 with GraphQL `Class(ids: [...])` at the selected revision (branch or commit path); if the pinned server rejects `ids` for any class or returns a shape the mapping cannot decode, the fallback is per-id document `GET` with concurrency 8. No filter other than `ids` is pushed to the backend in M05; every predicate is evaluated in the application on decoded `NodeRecord`s, so semantics are identical for every storage path. Relationship and property filters load the subject's readable assertions from the candidate set (assertions are candidates too). Pushdown of further filters is deferred to M13 after measurement. | GraphQL `ids` is covered by upstream tests; nested subdocument filters are not, so they are not relied on. Proof: `test_backend_fetch.py` on the real stack with 200 ids per chunk and a historical commit. |
| D4 | **Ordering and cursors.** Total order by the chosen `order` key with canonical IRI as the final tiebreak. Cursor = base64url of an HMAC-SHA256-signed JSON `{v:1, revision, filter_digest, order, last_key, exp}` using `C1_CURSOR_SECRET` (new required setting, generated into `deployment/.env`); the cursor pins the content revision and the filter, never the authorization result; each continuation rebuilds the selection plan under current security state and continues after `last_key` (keyset pagination). Because pages are keyset-based, ordinary inserts after page one do not alter page one's captured content (pinned revision) and revocation before page two simply removes the revoked items. Cursors expire after 15 minutes and are rejected with 400 when tampered or expired. | Spec §6.1 "stable revision-bound pagination … every continuation rechecks"; PLAN M05-T05. |
| D5 | **Neighborhood traversal.** `GET /v1/entities/{id}/neighborhood?direction=out|in|both&predicates=<declared IRIs, required>&depth=1..3&limit&cursor`. Breadth-first over readable, active relationship assertions (object is an IRI) whose subject and object are both readable candidates; visited-node budget 500, edge budget 2000, time budget 2 s; response lists `nodes`, `edges` (assertion IDs and predicates), `truncated`, `budget`. Traversal continuation cursors also sign the frontier; a continuation whose selection plan differs from the one signed in the cursor (security state changed) returns 409 `restart_required` instead of continuing on stale traversal state. A visible endpoint connected only through a hidden assertion is never reached. | Spec §6.1 "neighborhood traversal bounded by direction, allowed relationship types, depth, visited resources, and time"; architecture §6.4 safe restart. |
| D6 | **Limits fixed by this milestone** (tested in M05-T06): page default 50, max 200; `ids` ≤ 200; traversal depth ≤ 3, nodes ≤ 500, edges ≤ 2000; request time budget 2 s (503 `C1-QY-053 time_budget` when exceeded, with no partial page presented as complete); candidate limit 5000; readable scopes < 500. Values live in `config.Settings` with these defaults and may be lowered but not raised above the spec's proposals without a report note. | Spec §6.1 proposed limits become fixed limits here. |
| D7 | **Errors.** Authentication 401; authorization on administration 403; hidden or nonexistent resource 404 with identical bodies; malformed ID, unknown filter, unsupported datatype, invalid temporal range 400 with `C1-QY-0xx` codes that never mention existence; limits 422; stale plan 409; backend or authorization service failure 503 without detail. Any attempt to pass raw query text (`woql`, `graphql`, `sparql`, `query` keys) is a 400 `C1-QY-002 unsupported_parameter`. | Spec §6.1 error classes; AGENTS.md §6.1 no escape hatch. |
| D8 | **Identity operations as ChangeSet operation kinds** (extends M04 D2): `resolve {candidates[], decision, rationale}` creates a `ResolutionRecord`; `merge {surviving_id, merged_id, alias_plan: copy|drop, assertion_plan: [{assertion_id, action: move|keep|retract}], rationale}`; `split {source_id, new_entity: record, assertion_plan: [...]}`; `undo_merge {resolution_id, reassignment_plan}`. The server expands each into concrete `create`/`replace` operations shown in the validation report: merged entity `lifecycle: superseded`; a `Redirect` record `{from, to, resolution}` from the new data-only profile `profiles/identity/` (class `Redirect`, installed through an M04 `install_profile` ChangeSet); moved assertions are `replace` operations changing only `subject` while each assertion keeps its own binding and scope; aliases copied as `altLabel` values on the survivor; nothing is guessed: a plan that omits an assertion is rejected (`C1-CS-040 incomplete_reassignment`). Authority: `contribute` on both entities and on every moved assertion, plus `review` for approval as in M04. Redirect resolution on `GET /v1/entities/{merged}` returns 200 with `redirected_to` only when both records are readable; otherwise 404. Duplicate candidates (`C1-IX-040`) are reported only for readable entities. | Spec F01 (explicit reassignment plan, redirects authorized, no guessing, history preserved); AGENTS.md §4.1. ADR-0014. |
| D9 | **Directory fixture** (`fixtures/directory/`): data-only profile `directory` (predicates `hasEmail`, `hasPhone`, `hasNote`, `memberOf`; reuse core `worksFor`); scopes `dir-shared`, `dir-company-a`, `dir-company-b`, `dir-selected`; entities Company A, Company B, Person (types include `schema:Person` as an extra RDF type), one shared email assertion in `dir-shared`, `worksFor` A and `worksFor` B in the respective company scopes, an A-only note in `dir-company-a`, a phone assertion in `dir-selected`; principals `alice` (reader `dir-shared`, `dir-company-a`), `bob` (reader `dir-shared`, `dir-company-b`), `carol` (reader of all four), `dave` (reader `dir-shared`, `dir-selected`); ingestion by `c1-svc-papertrader` through M04 ChangeSets approved by `carol` (reviewer). Expected outputs per principal are frozen in `fixtures/directory/expected/`. | PLAN §4 fixture family; A13; G6. |
| D10 | **Endpoints.** `GET /v1/catalog` (readable classes, declared predicates, datatypes, profile versions, fixed limits), `GET /v1/entities`, `GET /v1/entities/{id}`, `GET /v1/entities/{id}/neighborhood`, `GET /v1/assertions` (filters: subject, predicate, object, review_state, lifecycle, valid_at, competing_for=`{subject, predicate}` returning all readable competing claims), `GET /v1/sources`, `GET /v1/evidence`, `GET /v1/export?revision=&types=&cursor=` (authorized JSON-LD snapshot in pages using the M02 exporter; the same selection plan; never full history). Each list response carries `instance`, `revision`, `profile_versions`, `order`, `limit`, `count` (authorized count of the whole result set when candidates ≤ limit, else `count_bound: "≥ n"` with `truncated: true`), `next_cursor`, and `explain` entries per item naming the matched filters using only permitted metadata. Filters are query parameters for simple cases and a strict JSON body on `POST /v1/entities/search` for combined filters (read-only; same grammar). | Architecture §7; spec §6.1 response metadata. |

## 7. Recovery and security

| Failure point | Behavior |
|---|---|
| GraphQL `ids` unsupported or returns undecodable shapes | Per-id document GET fallback (proven), latency recorded; no semantic change. |
| ListObjects on scopes reaches the cap or the deadline | Query fails explicitly with `C1-QY-050`; never proceed on a partial set. |
| Journal unreadable or head changes mid-request | 409/503 fail closed; index discarded. |
| Index memory for 5000 candidates | Measured and recorded; the candidate limit may be lowered, not raised. |
| Cursor secret rotation | All cursors invalid (400); clients restart; documented. |

Sensitive values: the cursor signing key is generated into the ignored `.env` at stack start; checked-in files never contain it. No positive authorization cache: the index holds bindings (security state) keyed by an exact workflow head and is never used across heads; decisions still require the fresh `batch_read`.
