## 2. Goal and boundaries

**Observable result.** For every request and ChangeSet step, authorization decisions are identical to the current per-resource decisions under every security state that M03–M09 test, including injected faults, races and outages. Two kinds of cost change:
- Deterministic work counters fall: OpenFGA requests per authorized selection, journal listings and copies per decision step, and catalog-profile parses per readiness call.
- The measured software fixture load and lookup times fall correspondingly.

No positive authorization decision survives a request step.

**In scope.**
- Per-step security views built from one journal listing.
- A batched decision API on the authorization plane used by the planner, finalize, and the ChangeSet `_DecisionMemo`.
- An exact bulk `bound_to` source with a deterministic choice between bulk and per-resource reads.
- Caching of parsed trusted catalog profiles.
- Removal of whole-listing deep copies.
- Counters, equivalence tests, a performance report, and an ADR.

**Out of scope.**
- Changing the OpenFGA model, the binding semantics, the pending-operation semantics, or any error contract.
- Positive decision caches across requests.
- Any multi-host coordination, and direct (out-of-band) OpenFGA access.
- The M09 D12/D13 budgets. Defaults are unchanged; a later owner decision may lower the request budget.

**Invariants touched.** AGENTS.md §5.2 and §5.3; ADR-0009 (exactly one matching live tuple, a fresh check, and fail closed); ADR-0013 (every provisional resource is checked, and rechecked before release).

## 3. Decisions to resolve

| ID | Decision | Rationale, evidence, proof obligation |
|---|---|---|
| D1 | **Per-step security view.** One immutable view is built from a single `Journal` listing at one data version. It holds bindings by resource, scopes by ID, and a pending-operation index by resource target and by scope (kinds `scope_create`, `scope_retire`, `membership`). The view records the data version it was built from. Every decision step re-reads the journal head before and after, exactly as `_resource` does now, and a changed head still yields `security_revision_changed`. The view never outlives one request step. | Removes the 42% copy cost and is semantically identical: the current code already reads one version-keyed listing and only rescans it per call. Proved by T01 and T02. |
| D2 | **No whole-listing deep copies.** `Journal.list`/`list_many` return read-only views (tuples of `MappingProxyType`, or frozen validated models) that callers cannot mutate. Mutation through a returned value raises an error. The M08 unit test that asserted copies is changed to assert immutability. | Isolation is kept without O(journal) copying per call. Proved by a unit test and T01. |
| D3 | **Batched plane decisions.** `AuthorizationPlane.check_many(principal, ids, relation)` returns a `Decision` per ID. It uses D1 for binding, scope and pending state, the `bound_to` source (D4), and BatchCheck in chunks of 50. Sequential fresh checks remain the fallback if BatchCheck fails (ADR-0009). `_resource` becomes `check_many` with one ID, so there is a single decision function, and reason codes are unchanged. The planner `_authorize`, finalize, and the ChangeSet `_DecisionMemo` (which pre-fetches each step's IDs in one call) use it. | One code path is equivalent by construction. Proved by T01 and the existing M03–M05 tests. |
| D4 | **Exact `bound_to` source.** There are two strategies, and both produce, for each requested resource, the full multiset of live `bound_to` users. (a) Per resource: today's read. (b) Store scan: a paginated whole-store Read without a tuple key (page size 100, `HIGHER_CONSISTENCY`), filtered to `relation == bound_to` and `object` type `resource`. The scan sees every tuple, including tuples from unknown scopes. The choice is deterministic and compares sequential round trips: scan when `ceil(journal binding count × 1.1 / 100) + 1 < ceil(requested IDs / 16)` (per-resource reads run 16 at a time); otherwise read per resource. *Implementation refinement: the first version compared request counts and scanned even for three IDs.* A scan aborts and fails closed on a non-advancing continuation, on more than 2,000 pages, or on any error (`security_unavailable`); it never returns partial results. Each strategy is bracketed by the same journal head checks. | The pinned v1.21.0 rejects every filtered bulk read (§1). A whole-store scan is the only exact batch. Its cost grows with total tuples, so the rule keeps small selections on per-resource reads. Proved by T01 and T03, plus unit tests of the choice rule. |
| D5 | **Catalog-profile parse cache.** `load_candidate` results, which come from immutable trusted files under `profiles/available/`, are cached per process. The key is the alias plus the SHA-256 of `profile.json`, `context.jsonld` and `shapes.ttl`. Each readiness call still reads the installed schema documents and marker freshly and compares them with the cached candidates (`detect_installed_registry` and `assert_installed_profiles` semantics unchanged). | A changed installed schema is still detected on the next call. Only file parsing is avoided. Proved by T05 and the existing M04/M08 profile tests. |
| D6 | **No positive cache across requests.** D1, D3 and D4 results live only within one request step or `_DecisionMemo` scope. Finalize performs a fresh D3 evaluation. | ADR-0009 and ADR-0013 are unchanged. Proved by T02. |
| D7 | **Deterministic work counters.** Test-only instrumentation counts OpenFGA requests by endpoint, journal listings, and catalog parses per operation. Gates assert ceilings on these counters, not wall-clock times. Wall-clock times are measured and reported. Ceilings on the software fixture: one lookup makes at most `ceil(tuples/100) + 2` reads per authorization pass, plus `ceil(ids/50)` BatchChecks and one ListObjects. A ChangeSet step makes at most one journal listing per decision step. A readiness call parses zero catalog files when they are unchanged. | Host-independent gates. The laptop host's variance made wall-clock gates unreliable (M09 attempts). |

## 7. Recovery and security

| Failure point | Expected safe behavior and recovery |
|---|---|
| OpenFGA unavailable during a scan or BatchCheck | `security_unavailable` or 503. No partial selection; no fallback to cached allows. |
| The journal head changes during a step | `security_revision_changed` or 409 restart, as today. |
| A tuple from an unknown scope (out-of-band write) | The scan sees it, and the resource is denied as `inconsistent_binding` (M03-T05 parity). |
| A catalog file changes on disk | The digest key differs, so the file is re-parsed. Readiness compares fresh schema reads. |
| A view mutation attempt in code | An immediate error; detected by the unit tests. |
