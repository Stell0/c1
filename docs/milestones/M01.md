## 2. Goal and boundaries

**Result.** A pinned local reference stack (TerminusDB, OpenFGA with PostgreSQL, Keycloak) started by one command, an artifact and license inventory, ADRs recording verified and rejected assumptions, and executable probes with recorded PASS/FAIL for transactional writes, stale-base rejection and lost-response reconciliation, historical revision reads, authorization freshness, interrupted publication, and interchange round-trip. This gives G1 evidence and the foundational parts of G2, G3, G4, and G8.

**Boundaries.** Probes live in `probes/` and `tests/integration/m01/`, outside `src/c1`, and are not a product or an exposed service. No HTTP API, no product schema profile, no fixture families from PLAN.md §4, no Explorer. No additional database, no vectorlink, no insecure user header, no enterprise or cloud feature. Direct backend access is confined to these probes (PLAN.md §4 test rules).

**Invariants.** AGENTS.md §4.2 (three authorities, no new database), §4.3 (knowledge operations and receipt commit together or not at all), §5.2 (no distributed transaction assumed; inconsistent publication must not expose content; missing security state fails closed).

## 3. Decisions to resolve

| ID | Decision | Rationale, evidence, and proof obligation |
|---|---|---|
| D1 | **Service pins** (ADR-0003): the four images and digests in §1. TerminusDB runs with basic admin authentication on the private compose network. OpenFGA uses the postgres datastore. Keycloak runs in development mode with an imported synthetic realm file. Excluded with recorded reasons: vectorlink (AI component), `TERMINUSDB_INSECURE_USER_HEADER` (authentication bypass), TerminusCMS and any cloud-only feature. | `scripts/inventory.py` records tag, repository digest, image config digest from `podman image inspect`, extracted license text with its SHA-256, and notice presence into `docs/evidence/M01/inventory.md`. M01-T01 fails on any mismatch with ADR-0003. |
| D2 | **TerminusDB access through its HTTP API with httpx** (ADR-0004). The official Python client is rejected for M01: it excludes Python 3.12+, contradicting D1 of M00, and its PyPI classifier disagrees with its repository license. Operations exercised: database create and delete; schema insert; multi-document insert, replace, and delete with `author` and `message`; `TerminusDB-Data-Version` as expected head; `/api/document/.../local/commit/{id}`; `/api/history`; `/api/log`; `/api/diff`. JWT authentication is noted but not needed in M01. | Each operation's request, response shape, and status codes are recorded in ADR-0004 as verified or rejected. |
| D3 | **Knowledge head versus workflow bookkeeping** (ADR-0005). Knowledge lives in database `c1`, branch `main`. Workflow records (ChangeSet drafts, validation reports, apply receipts, publication journal) live in a separate database `c1_workflow` on the same TerminusDB server. This is the same backend, not a second knowledge store. Every knowledge commit's `message` carries `changeset=<id> digest=<sha256>`, so the knowledge commit itself is the durable receipt; the `ApplyReceipt` in `c1_workflow` is a projection written afterwards. Reconciling a lost response scans `/api/log` of `c1` for the digest. Writes to `c1_workflow` never touch the head of `c1`, so bookkeeping cannot make a proposal stale against itself. | Proven by M01-T02, T03, T06. If the proof fails, the bounded alternative is a journal in PostgreSQL; that is an architecture change requiring owner approval, not a silent fallback. |
| D4 | **Write serialization**: a process-wide asyncio lock in the probe writer, plus the expected-head header on every knowledge write as defense in depth. | Proven by M01-T03. |
| D5 | **Authorization plane prototype** (not the M03 model): OpenFGA model with types `user`, `group` (`member: [user]`), `scope` (`reader: [user, group#member]`), `resource` (`bound_to: [scope]`, `reader: reader from bound_to`). Every check uses consistency `HIGHER_CONSISTENCY`; server caching flags stay at their defaults (disabled). Store id and model id are written to `deployment/.env` by the bootstrap script. | Proven by M01-T05. The M03 plan defines the real model; this one exists only to test freshness mechanics. |
| D6 | **Publication journal and read gate** (`probes/publication.py`): journal document `{id, resource_id, scope_id, state, knowledge_commit}` with `state ∈ {pending, content_written, binding_written, complete, failed}` stored in `c1_workflow`. The reader path allows a read only when the journal state is `complete` and the OpenFGA check allows. The restart reconciler completes pending operations idempotently (tuple writes are idempotent by content) or marks them `failed` and writes a deny tombstone tuple. Crash points are selected by the environment variable `C1_PROBE_CRASH_AFTER ∈ {journal, content, binding}` and implemented with `os._exit`. | Proven by M01-T06. Measured journal write latency is recorded in the report. |
| D7 | **Fault injection mechanics**: process crash via D6; service outage via `podman kill`; timeouts via `podman pause`; egress denial for interchange probes by setting `HTTPS_PROXY=http://127.0.0.1:9` and `HTTP_PROXY` to the same sink so any remote fetch fails immediately. | Used by M01-T06 and the negative case of M01-T07. |
| D8 | **Stack runner**: `podman compose` (podman-compose 1.5.0), exposed in the Makefile as `COMPOSE ?= podman compose`. All host ports bind to `127.0.0.1`. Named volumes are prefixed `c1-dev-`. `deployment/.env.example` holds synthetic credentials; `deployment/.env` is ignored by git. Services get memory limits and health checks; `up --wait` gates on health. | The Docker CLI on the host lacks the compose plugin. If podman networking fails, the recorded fallback is the Docker daemon with the podman-compose provider, noted in the report. |
| D9 | **Interchange probe**: rdflib 7.6.0 and pyshacl 0.40.1. Fixture `probes/fixtures/assertion.jsonld` with a bundled context file `probes/fixtures/context.jsonld`: one named statement resource with subject, predicate, object, a label `"Tesla"@en`, an `xsd:decimal` value, and a PROV activity with `prov:wasGeneratedBy` and `prov:wasAttributedTo`. Round trip: JSON-LD → rdflib graph → SHACL validation against `probes/fixtures/shape.ttl` → mapping to a TerminusDB document under a probe schema → read back → JSON-LD → rdflib graph → `rdflib.compare.isomorphic`. Remote contexts are never fetched: the loader resolves only bundled contexts and raises on anything else. | Proven by M01-T07. The mapping is a probe, not the M02 storage mapping. |
| D10 | **Layout**: `deployment/compose.yaml`, `deployment/.env.example`, `deployment/keycloak/c1-dev-realm.json`, `deployment/openfga/model.fga`, `probes/` (package: `terminus.py`, `fga.py`, `publication.py`, `interchange.py`, `fixtures/`), `tests/integration/m01/test_t01_inventory.py … test_t07_interchange.py` marked `integration` and skipped unless `C1_STACK=1`, `scripts/inventory.py`, `docs/decisions/ADR-0003-service-pins.md`, `ADR-0004-terminusdb-access.md`, `ADR-0005-knowledge-head-and-workflow.md`, `docs/evidence/M01/`. | Keeps proofs isolated from product code (PLAN.md §2: "foundation experiments stay isolated"). |

## 5. Test implementation

| Test | Executable form | Fixture and expected result | Failure condition |
|---|---|---|---|
| M01-T01 Open-source artifact check | `test_t01_inventory.py` | `inventory.md` lists each mandatory image with tag, repository digest, config digest, license text SHA-256, and notice presence, matching ADR-0003. The probe code imports only packages in `uv.lock`. No enterprise or cloud flag appears in `compose.yaml`. | Digest or license mismatch, missing license file, or a forbidden flag. |
| M01-T02 Atomic batch | `test_t02_atomic.py` | Insert three documents in one request where the third violates the schema (missing required field). Expect HTTP 4xx, `/api/log` unchanged, none of the three readable. Then insert a valid batch of three with `message` carrying a digest: exactly one new commit, all three readable at the new head, and `c1_workflow` receipt written after it. | Any partially visible document, more than one commit, or a receipt without a matching commit. |
| M01-T03 Stale base and lost response | `test_t03_stale_and_reconcile.py` | Writers A and B read head H. A commits (H → H1). B writes with `TerminusDB-Data-Version: H`: expect HTTP 400 `data_version_mismatch` and the log unchanged since H1. Then commit with digest D and discard the response; the reconciler scanning `/api/log` finds exactly one commit with D; a retry with the same D performs no write. | A lost update, a duplicate commit for D, or a reconciler miss. |
| M01-T04 Independent revisions | `test_t04_revisions.py` | Write v1 then v2 of one document. Read `/local/commit/{c1}` and `/local/commit/{c2}`; values differ as expected. The historical document contains no field that the reader path consults for authorization; the reader path calls only the journal and OpenFGA. | Wrong value at either commit, or any authorization decision derived from document content. |
| M01-T05 Fresh policy check | `test_t05_freshness.py` | User u is a member of group g; g is reader of scope S; resource r is bound to S; check allows. Re-bind r to S2 (delete tuple, write tuple) while u stays in g: next check denies. Separately revoke g's reader relation on S and restore r's binding: check denies. | Any allow after a change. |
| M01-T06 Interrupted publication | `test_t06_publication.py` | For each crash point in `{journal, content, binding}`, run the publisher as a subprocess with `C1_PROBE_CRASH_AFTER` set. Assert the read gate blocks the resource while the journal state is not `complete`. Restart the reconciler. Assert the final state is either `complete` with an allowing check or `failed` with a deny tombstone, and that content was never readable without a valid binding. Record journal write latency. | Readable content during a pending state, or an inconsistent final state. |
| M01-T07 Interchange probe | `test_t07_interchange.py` | Round trip per D9 is isomorphic; the language tag `@en`, the `xsd:decimal` datatype, the statement IRI, and the PROV links survive. Negative: an input referencing a remote context not in the bundle is rejected with a diagnostic, nothing is persisted, and no outbound request occurs (egress sink per D7). | Non-isomorphic graphs, lost tag or datatype, persistence after rejection, or an outbound fetch. |

Mocks are not used in any of these tests. Every test names its TerminusDB database and OpenFGA store uniquely and cleans them up.

## 7. Recovery and security

| Failure point | Behavior |
|---|---|
| Image pull fails | Record `NOT_RUN` for dependent tests with the registry error; do not substitute another tag. |
| TerminusDB multi-document insert is not atomic | T02 FAIL is a blocker. Propose a bounded revision to the owner (for example, single-document-per-commit with a compensating design), do not add a database. |
| Journal write latency unacceptable | Record the measurement; the M03 plan decides whether the journal location changes. |
| Podman networking fails | Use the Docker daemon with the podman-compose provider and record the deviation. |
| OpenFGA unavailable | Reader path denies; verified as part of T05 teardown with `podman kill`. |

Rollback: `make stack-reset` destroys development volumes only; probe databases and stores are per-test and removed at teardown. Permissions: only synthetic principals in the development realm and store. Secrets: `deployment/.env` untracked; probe logging scrubs `Authorization` headers; evidence excludes `.env` and any token.
