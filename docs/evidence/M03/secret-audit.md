# M03 offline detector audit

**Date:** 2026-09-27
**Detector:** pinned `detect-secrets` 1.5.0 with its default plugins and filters
**Result:** 16 findings audited as false positives; no detector settings changed.

The offline scan covered 241 Git-cached and nonignored untracked files, with
network verification disabled. Eleven high-entropy matches in
`docs/evidence/M03/dependencies.json` are SHA-256 values for public package
license files. Each was recomputed from the corresponding installed file and
matched. The packages are FastAPI, Starlette, Uvicorn, PyJWT, cryptography
(three license texts), cffi, pycparser, click, and annotated-doc.

Five test-source detections are deterministic fixtures: secret-keyword matches
in `tests/unit/m03/test_api_boundary.py:153`, `test_config.py:26`,
`test_journal.py:16`, and `test_tokens.py:35`, plus a Basic Auth match at
`test_config.py:47`. These literals occur only in unit-test code and none
matches the ignored deployment credentials. The Basic Auth fixture targets a
loopback address and uses generic test credentials.

Exactly these 16 scanner fingerprints were added to `.secrets.baseline` with
`is_secret: false`. Existing reviewed findings were preserved. The evidence
logs contain no bearer token, JWT, or private-key pattern. No detector, filter,
threshold, or exclusion was changed. `make secrets` is the final offline gate.

After the baseline update and report were present, the repeat scan covered 247
files and found 51 total detections, all matching audited baseline entries.
`make secrets` passed for those 247 tracked and nonignored files.
A subsequent `make secrets` also passed after concurrent test evidence raised
the scanned file count to 249.

A final privacy-fixture failure capture added two identical high-entropy
detections at `integration.log:611` and `junit.xml:84`. They are the same
request-path shape, `/stores/<generated-id>/read`, emitted by the integration
`live_case()` fixture after it creates a disposable OpenFGA store for that test.
The store identifier is generated by OpenFGA, is not a credential, and is not
configured in `deployment/.env`; the matching request uses the normal service
authorization header separately. The exact scanner fingerprint was marked as a
false positive at those two log locations. No raw identifier was copied into
this audit. Detector and filter settings remain pinned defaults.
